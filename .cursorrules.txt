[신원 확인]
나는 오늘밤빠(bchata.vercel.app) 창업자다. 너는 내 지시만 따르는 AI 개발 보조다. 아래 규칙은 예외 없이 적용되는 절대 명령이다.

# 절대 규칙

## 작업 원칙
1. [단일 파일 수정] 지정된 파일 1개만 수정할 것. 허락 없이 여러 파일 동시 수정 금지
2. [새 파일 생성 금지] 임의로 새 파일 생성하지 마라
3. [전체 읽기 필수] 수정 전 해당 파일 전체를 처음부터 끝까지 읽고 맥락 파악
4. [기존 코드 보존] 기존 코드 무단 삭제 금지. 교체 시 기존 코드는 주석(//)으로 남길 것
5. [임의 기능 추가 금지] 지시하지 않은 기능·테이블 연동 절대 추가 금지
6. [뇌피셜 금지] DB 스키마 불확실 시 추측 코딩 금지. 즉시 질문하고 답변 대기
7. [App.jsx 보호] 명시적 허용 전까지 절대 건드리지 마라

## 빌드·배포 원칙
8. [빌드 검증 필수] 수정 후 npm run build 실행하여 성공 여부 확인
9. [즉시 원복 및 보고] 빌드 실패 시 즉시 원복 후 에러 로그와 함께 보고
10. [자동 배포] 빌드 성공 후 git add . && git commit -m "feat/fix: 요약" && git push origin main 직접 실행
11. [main 브랜치 고정] 허락 없이 별도 브랜치 생성 금지. 항상 main에서만 작업
12. [AI 직접 실행] 터미널 명령어를 나에게 시키지 마라. git, npm 등 Cursor 본인이 직접 실행

## 보고 원칙
13. [간결한 보고] 장황한 설명 금지. 수정한 코드 블록과 배포 결과만 보고
14. [설명 텍스트 금지] 터미널에 설명 텍스트·주석 입력하여 에러 발생시키지 마라

## 코드 원칙
- TypeScript 사용 필수 — any 타입 사용 금지
- 함수명·변수명은 영어로 작성
- 주석은 한국어로 작성
- 에러 처리 반드시 포함
- 환경변수는 .env.local에서만 불러올 것
- console.log 절대 추가 금지

## DB 원칙
- DB 테이블 구조 임의 변경 금지
- README.md 정의된 테이블 구조 그대로 사용
- UUID는 Supabase 자동 생성 사용

## 매칭 로직 원칙
- 매칭 우선순위 임의 변경 금지
- 교통약자 → 남은 역 수 → 요청 시각 순서 유지
- 혼잡도 7 이상 시 기능 정지 로직 포함
- 노쇼 3회 누적 시 7일 정지 로직 포함

## 개발 서버 원칙
- 포트 충돌 시 기존 프로세스 종료 후 3000으로 실행
- 서버 시작 전 3000 포트 사용 여부 확인
- 500 에러 발생 시 즉시 원인 파악 후 수정
